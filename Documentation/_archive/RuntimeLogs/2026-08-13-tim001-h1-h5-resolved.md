## The two engine bugs that blocked H5 (root cause)
1. **Stale `AIPlayer` position** — `CombatAI.detectNearbyEnemy()` computes enemy distance from
   `aiPlayer.getX/Y/Z`, but `FleetPlay`'s `BotLoop` never updated the player's position after
   construction (seeded `0,0,0`). Every hostile therefore read as ~83k units away → the bot stayed
   `AUTO_PLAY` and never engaged, regardless of where it actually stood. **Fix:** `FleetPlay` now
   calls `player.setPosition(snapshot.x, snapshot.y, snapshot.z)` every tick before `makeDecision()`.
2. **Missing attack target objId** — `engageEnemy()` returns plain `CombatDecision.attack()` which
   carries no target id. `FleetPlay` passed `parseObjId(decision.getTargetId())` → `0`, so
   `CombatFramePlanner` produced **no** Action/AttackRequest frames (live log:
   `SKIP-UNPROVEN ... planner produced no frames`) → attacks decided but nothing sent. **Fix:**
   pass the `CombatAI`'s actually-selected `getSelectedTargetObjId()` to `executeCombat`.

Regression lock: `CombatFramePlannerTest.testPlainAttackDecisionWithResolvedObjIdProducesFrames`.
